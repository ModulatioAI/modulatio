# 0.9.0 Wild Bill Verdict

Verdict: **SIGN-OFF-WITH-RESERVATIONS**

I did not find a reachable merge blocker in the 0.9.0 pre-ship branch. The load-bearing fixes
I traced are engine-enforced rather than left to prose: cross-goal dependency status is resolved
from the store, durable read-modify-write text paths decode strictly, the dispatch breaker keeps
hard/no-commit backstops while narrowing only the structured-family repetition false positive,
binary assembly output files are moved onto the real deliverable on the tool-loop path, `run_shell`
does not use `preexec_fn`, and the new cron/heartbeat/auth/budget locks cover the RMW windows.

## Findings

No BLOCKER/HIGH findings.

### LOW / Follow-up: raw-thread regression tests can still hide the next thread failure as a warning

- `docs/design/0.9.0-flaky-thread-warning.md:94`
- `docs/design/0.9.0-flaky-thread-warning.md:97`

The captured source of the nondeterministic `PytestUnhandledThreadExceptionWarning` is a raw
thread in `tests/test_heartbeat.py::test_cancel_not_clobbered_by_concurrent_update`, not the
wave executor. That makes it non-blocking for merge, but the test harness should still wrap raw
thread targets with `try/except -> errors.append(exc)`, join them, and assert `not errors`. Until
that cleanup lands, a future real thread exception can again appear as a suite warning instead of
a localized failing test.

The three path parity claim holds in the current tree. Initial execution validates typo/unknown
deps by filtering out only store-resolved cross-goal ids before topo sort; a truly unknown id
remains and rejects the task plan. Concurrent waves receive the store-resolved cross-goal status
map and `_ready_wave` admits only COMPLETED deps. Sequential fallback and resume both call the
shared `_dep_failed`, `_unknown_deps`, and `_unready_deps` gates, so FAILED blocks, UNKNOWN blocks,
not-yet-COMPLETED waits, and COMPLETED admits.

The named durable RMW surfaces decode with `encoding="utf-8"` and no `errors="replace"`, so they
will not persist U+FFFD into operator-approved text. The remaining `errors="replace"` uses I saw
are cache/index/credential/log/read-only readers or subprocess/network output where substitution
is the intended fail-open posture.
